# v0.14 Simon: generics and traits

## Context

v0.14 adds generics ("type slots") and traits. The design was settled in conversation on 2026-11-02 and reviewed on 2026-11-06:
- Go-like syntax: `func first[T](xs: []T) -> T`, `struct Stack[T]`, `union Result[T, E]`, constraints `[T: Shape]`.
- Generic code is checked when written: `T` is opaque and only what its constraint allows is legal.
- One compiled copy per filled type (monomorphization in sema). No vtables; bytecode, VM and GC are unchanged.
- `trait` holds method signatures only. Conformance is structural, and errors are reported where a type is used as `T`.
- `+` combines traits ("and"); `|` builds a type list ("or") and binds tighter. Type lists hold primitives only (`int`, `float`, `byte`, `string`, `bool`). An operator is legal on `T` when every member supports it. A named list (`trait Number = int | float`) replaces a built-in `Number`.
- Slots are filled from the arguments first, then from the expected type (annotation, `@()`, param/field/return type). There are no explicit `[int]` arguments in expressions in 0.14.
- `mut x: T` is allowed only when `T` has a trait constraint (its `mut self` methods need it). `mut list: []T` is always allowed, since the array itself can change.
- `==` and `!=` on `T` are allowed only when `T` is constrained by a type list. Unconstrained `T` rejects them, since they would mean pointer equality for strings, structs and arrays.
- Out of scope: method-level slots, a trait as a parameter type, trait values, fields in traits. Auto-dispatch unions stay a Low backlog idea.
- v0.14 work goes on the `type-slots` branch, on top of the released v0.13.

## Architecture (sema only)

**New type kind `slot`** in `src/type_table.zig` (`Type.kind`): `{ name, constraint }`. The constraint is a flattened list of trait methods plus an optional primitive type list. Every declared slot gets its own type id, so `T` only coerces to the same `T`.

**Generic declarations are templates.** In `hoistDeclarations` (`src/sema.zig`), a declaration that has slots becomes a `generic` symbol kind, holding the AST node, its slot list and an instance cache keyed by type-argument ids. It isn't fulfilled or visited like a normal declaration.

**Two passes per generic:**
1. **Opaque check.** This runs once, when visiting the declaration. Slot names are bound to their `slot` type ids in a child scope, then the existing `fulfillFuncType` / `visitFnDef` / `visitStructDef` path runs. The IR is thrown away; this pass exists only to report errors at the definition. Each place that needs a rule for `slot`:
   - `canCoerce` / `coerceValue`: `T` only to `T`. A literal fits `T` if every member of the type list accepts it.
   - `evalBinaryExp` / `evalUnaryExp`: allowed only for type lists where every member supports the operator (including `==` / `!=`).
   - method calls in `evalFnCall`: resolved from the constraint's trait methods.
   - indexing, `len`, `append`, `copy`, interpolation and `echo` work on `[]T` / `T` as they do for any type.
   - `mut` params of slot type: an error unless the slot has a trait constraint.
   - For sharing rules (`isChangeableType`, `canBeChangedThrough`), `T` is treated conservatively as a possibly-heap value.
2. **Copies (instantiation).** Each new set of type arguments gets a cache entry immediately, which handles recursive types like `Node[T]` with `next: ?Node[T]`. This reuses the hoisting pattern `createEmpty*Symbol` + `fulfill*Type`, with slot names bound to concrete ids. The signature is fulfilled immediately, so the call site gets a uid, params and return type. Lowering the body is pushed onto a worklist that is drained after the main visit in `analyze`, next to `checkPendingWhens`. Nothing is ever visited while inside another function's scope. A generic type's copy fulfills and lowers all its methods. Names are `first[int]` and `Stack[[]int]`, used in `type_table.name` and in errors. A depth cap (e.g. 64 nested copies) produces an error instead of runaway recursion like `f[T]` calling `f[[]T]`.

**Rules for copies:**
- **Copies filled with slots are signature-only.** Inside a generic's opaque check, `Stack[T]` or `first[T]` gets filled with the slot `T` itself. That copy only produces the type (fields, method signatures, return type) and is never pushed onto the worklist. Only fully concrete copies are lowered.
- **Sharing analysis runs per copy.** The flow frames from v0.13 are per function, so each copy is analyzed again. Because the opaque check treats `T` as possibly heap (the strictest case), every sharing error should already show up at the definition. If a copy still reports one, the error says which copy it came from (`in first[[]int]`).
- **Inferred error sets are per copy.** `func parse[T](...) -> !T` gives each copy its own inferred set, since each copy is its own function.
- **No defaults on slot-typed params.** A parameter whose type mentions a slot can't have a default value (defaults are constants and can't fit an unknown `T`). New error.

**Inference.** Unify each param's type annotation (AST, with slot names) against the argument's type: `[]T` against an array, `?T` against a nullable, `Stack[T]` against a copy (each copy records its generic and its arguments). Arguments whose param type has no slots are evaluated with that type as the expected type, the rest without one. Unfilled slots are then taken from the expected type, which `evalFnCall` / `evalExpectedStructInit` have to receive (today `evalFnCall` takes no expected type: thread it through from `evalExpWithContext`). New errors:
- `CantInferSlot` (also raised for an empty `[]` with nothing to infer from)
- `ConflictingSlotTypes` (`int` vs `float` — no implicit conversion during inference)
- `GenericNeedsCall` (a generic function used as a value)
- `void` or error unions as type arguments
- a default value on a slot-typed param
- `mut` on a param of an unconstrained slot type

**The AST-keyed maps** `exp_types` / `exp_symbols` are overwritten on every visit, and flow is resolved per function, so visiting the same AST once per copy is safe as long as copies are visited one after another (the worklist guarantees this).

## Syntax (parser/AST)

- `src/lexer.zig`: new `trait_kw`.
- `src/ast.zig`:
  - `FuncStmt`, `StructStmt` and `UnionStmt` get `slots: []const Slot`, where `Slot = { identifier, constraint: ?*Constraint, loc }`.
  - A constraint is a list of terms joined by `+`; each term is either a trait name or a type list (`int | float`).
  - `TypeAnnotation.struct` gets `args: []const *TypeAnnotation` (`Stack[int]`, `Result[[]T, E]`).
  - New `Statement.trait`: either `{ parents, methods }` (signatures only), or `{ types }` for `trait Number = int | float`.
- `src/parser.zig`:
  - `parseFuncStmt` / `parseStructStmt` / `parseUnionStmt` parse an optional `[...]` after the name.
  - `parseTypeAnnotation` parses `Name[args]`.
  - Trait methods are `func name(params) -> Type` with no body. `@` means the conforming type.
- Enums and error sets get no slots (they would be a parse error).

## Phases

Each step is one commit with tests, and a changelog bullet under `### Features` when it changes what users can write. Each phase starts only after the user's go-ahead.

0. **Open v0.14.** Changelog section and version `0.14.0-devel` (done), phase list in `.claude/tasks/in-progress.md` (done), roadmap "Meta structs" → "Traits", language-ref version line.
1. **Generic functions, unconstrained.**
   - **1a. Syntax and the slot type.** Lexer/AST/parser for `[T, U]` after a `func` name, the `slot` type kind, the `generic` symbol and the opaque check. A generic function compiles and is checked, but calling it is an error until 1b. Tests: parser errors (`func f[]`, `func f[T,]`), opaque-check errors (`+` on unconstrained `T`, `T` assigned from `int`, `==` on unconstrained `T`, `mut x: T`, a default on a `T` param).
   - **1b. Copies and inference from arguments.** Instance cache, worklist, signature-only copies for slot arguments, depth cap, copy names. Tests: `first`, `swap` on arrays, `reverse`, generic calling generic, recursion, `?T`, `[][]T`, two copies in one program (`sum([1, 2])` and `sum([0.5, 1.5])`), inferred error sets per copy; errors for conflicting slots and a generic function used as a value.
   - **1c. Inference from the expected type.** Thread the expected type into `evalFnCall`; `CantInferSlot`. Tests: `let xs: []int = empty()`, a return or argument giving the type, `[]` with nothing to infer from.
2. **Generic prelude signatures.** `extern func` with slots in `src/prelude.dsk`; `append[T](mut array: []T, value: T)` and `copy[T](value: T) -> T` replace their `dynamic` signatures, which also makes `append` check its item type (backlog bug). `echo` keeps `dynamic` until there's a `Printable` trait. Natives stay one binding shared by every copy (signature-only instantiation).
3. **Generic structs and unions.**
   - `Stack[T]` in annotations, construction by inference / `@()` / annotation, methods using `T` and `@`
   - recursive `Node[T]`, generic types used inside generic functions (`Stack[T]`, signature-only), constant static fields (shared by all copies)
   - wrong slot count (`Stack[int, int]`, a bare `Stack` in a type), and `when` on `Result[T, E]` copies
4. **Traits.**
   - `trait` declarations; composition `trait A: B + C` (flatten; errors for clashing signatures and cycles); constraints `[T: A + B]`
   - trait method calls on `T` in the opaque check, including `mut self` needing a mutable receiver; `mut x: T` allowed with a constraint
   - structural conformance check on each copy: `DoesntFitTrait`, naming the missing method or the signature difference
   - `@` replaced by the conforming type
5. **Type lists.**
   - `[T: int | float]`, `trait Number = int | float`, primitives only
   - which operators are legal per member set (e.g. `%` not with `float`), `==` / `!=` on `T`; literals fitting `T`
   - `|` binding tighter than `+`; mixed `Number + Printable`
6. **Docs.** Add a generics and traits section to `doc/language-ref.md`, finish the roadmap and changelog, and run the full tests and build.
