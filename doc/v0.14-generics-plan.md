# v0.14 Simon: generics and traits

## Context

v0.14 adds generics ("type slots") and traits. The design was settled in conversation on 2026-11-02:
- Go-like syntax: `func first[T](xs: []T) -> T`, `struct Stack[T]`, `union Result[T, E]`, constraints `[T: Shape]`.
- Generic code is checked when written: `T` is opaque and only what its constraint allows is legal.
- One compiled copy per filled type (monomorphization in sema). No vtables; bytecode, VM and GC are unchanged.
- `trait` holds method signatures only. Conformance is structural, and errors are reported where a type is used as `T`.
- `+` combines traits ("and"); `|` builds a type list ("or") and binds tighter. Type lists hold primitives only (`int`, `float`, `byte`, `string`, `bool`). An operator is legal on `T` when every member supports it. A named list (`trait Number = int | float`) replaces a built-in `Number`.
- Slots are filled from the arguments first, then from the expected type (annotation, `@()`, param/field/return type). There are no explicit `[int]` arguments in expressions in 0.14.
- Out of scope: method-level slots, a trait as a parameter type, trait values, fields in traits. Auto-dispatch unions stay a Low backlog idea.
- v0.13 stays open for now (user choice). v0.14 work goes on `type-slots` on top of it.

## Architecture (sema only)

**New type kind `slot`** in `src/type_table.zig` (`Type.kind`): `{ name, constraint }`. The constraint is a flattened list of trait methods plus an optional primitive type list. Every declared slot gets its own type id, so `T` only coerces to the same `T`.

**Generic declarations are templates.** In `hoistDeclarations` (`src/sema.zig:592`), a declaration that has slots becomes a `generic` symbol kind, holding the AST node, its slot list and an instance cache keyed by type-argument ids. It isn't fulfilled or visited like a normal declaration.

**Two passes per generic:**
1. **Opaque check.** This runs once, when visiting the declaration. Slot names are bound to their `slot` type ids in a child scope, then the existing `fulfillFuncType` / `visitFnDef` / `visitStructDef` path runs. The IR is thrown away; this pass exists only to report errors at the definition. Each place that needs a rule for `slot`:
   - `canCoerce`: `T` only to `T`. A literal fits `T` if every member of the type list accepts it.
   - `evalBinaryExp` / `evalUnaryExp`: allowed only for type lists where every member supports the operator.
   - method calls in `evalFnCall` (`src/sema.zig:3152`): resolved from the constraint's trait methods.
   - indexing, `len`, `append`, `copy`, interpolation and `echo` work on `[]T` / `T` as they do for any type.
   - For sharing rules (`isChangeableType`, `canBeChangedThrough`), `T` is treated conservatively as a possibly-heap value.
2. **Copies (instantiation).** Each new set of type arguments gets a cache entry immediately, which handles recursive types like `Node[T]` with `next: ?Node[T]`. This reuses the hoisting pattern `createEmpty*Symbol` + `fulfill*Type`, with slot names bound to concrete ids. The signature is fulfilled immediately, so the call site gets a uid, params and return type. Lowering the body is pushed onto a worklist that is drained after the main visit in `analyze` (`src/sema.zig:56`), next to `checkPendingWhens`. Nothing is ever visited while inside another function's scope. A generic type's copy fulfills and lowers all its methods. Names are `first[int]` and `Stack[[]int]`, used in `type_table.name` and in errors. A depth cap (e.g. 64 nested copies) produces an error instead of runaway recursion like `f[T]` calling `f[[]T]`.

**Inference.** Unify each param's type annotation (AST, with slot names) against the argument's type: `[]T` against an array, `?T` against a nullable, `Stack[T]` against a copy (each copy records its generic and its arguments). Arguments whose param type has no slots are evaluated with that type as the expected type, the rest without one. Unfilled slots are then taken from the expected type, which `evalFnCall` / `evalExpectedStructInit` have to receive (today `evalFnCall` takes no expected type: thread it through from `evalExpWithContext`). New errors:
- `CantInferSlot` (also raised for an empty `[]` with nothing to infer from)
- `ConflictingSlotTypes` (`int` vs `float` — no implicit conversion during inference)
- `GenericNeedsCall` (a generic function used as a value)
- `void` or error unions as type arguments

**The AST-keyed maps** `exp_types` / `exp_symbols` are overwritten on every visit, and flow is resolved per function, so visiting the same AST once per copy is safe as long as copies are visited one after another (the worklist guarantees this).

## Syntax (parser/AST)

- `src/lexer.zig`: new `trait_kw`.
- `src/ast.zig`:
  - `FuncStmt`, `StructStmt` and `UnionStmt` get `slots: []const Slot`, where `Slot = { identifier, constraint: ?*Constraint, loc }`.
  - A constraint is a list of terms joined by `+`; each term is either a trait name or a type list (`int | float`).
  - `TypeAnnotation.struct` gets `args: []const *TypeAnnotation` (`Stack[int]`, `Result[[]T, E]`).
  - New `Statement.trait`: either `{ parents, methods }` (signatures only), or `{ types }` for `trait Number = int | float`.
- `src/parser.zig`:
  - `parseFuncStmt` / `parseStructStmt` / `parseUnionStmt` parse an optional `[...]` after the name.
  - `parseTypeAnnotation` (`src/parser.zig:1447`) parses `Name[args]`.
  - Trait methods are `func name(params) -> Type` with no body. `@` means the conforming type.
- Enums and error sets get no slots (they would be a parse error).

## Phases (one commit each, tests + changelog in each)

0. **Open v0.14.** Add a changelog section, update the roadmap ("Meta structs" → "Traits"), write the phase list to `.claude/tasks/in-progress.md`, and set the language-ref version line.
1. **Generic functions, unconstrained.** Lexer/AST/parser for slots on `func`; `slot` type kind; generic symbol; opaque check; copies plus the worklist; inference from arguments and from the expected type; the errors above. Tests:
   - success: `first`, `swap` on arrays, `reverse`, generic calling generic, recursion, `?T`, `[][]T`
   - error: `+` on unconstrained `T`, `T` assigned from `int`, can't infer, conflicting slots, generic function as a value
2. **Generic structs and unions.**
   - `Stack[T]` in annotations, construction by inference / `@()` / annotation, methods using `T` and `@`
   - recursive `Node[T]`, generic types used inside generic functions (`Stack[T]`), constant static fields (shared by all copies)
   - wrong slot count (`Stack[int, int]`, a bare `Stack` in a type), and `when` on `Result[T, E]` copies
3. **Traits.**
   - `trait` declarations; composition `trait A: B + C` (flatten; errors for clashing signatures and cycles); constraints `[T: A + B]`
   - trait method calls on `T` in the opaque check, including `mut self` needing a mutable receiver
   - structural conformance check on each copy: `DoesntFitTrait`, naming the missing method or the signature difference
   - `@` replaced by the conforming type
4. **Type lists.**
   - `[T: int | float]`, `trait Number = int | float`, primitives only
   - which operators are legal per member set (e.g. `%` not with `float`); literals fitting `T`
   - `|` binding tighter than `+`; mixed `Number + Printable`
5. **Docs.** Add a generics and traits section to `doc/language-ref.md`, finish the roadmap and changelog, and run the full tests and build.

**To ask the user when the phase gets there** (not settled yet):
- whether `mut x: T` is allowed. My lean: allowed only when `T` has a trait constraint, and enums with methods are handled.
- whether `==` on `T` is allowed. My lean: type lists only, since unconstrained `==` means pointer equality for strings and structs.
