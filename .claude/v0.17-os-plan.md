# std/os (v0.17): implementation plan

Started 2026-11-17 on `v017std`, based on `v017` at `1225e8e`.
Status: planning complete; implementation has not started. The user requested std/os planning and approved platform identification. Remaining API details below are recommended defaults, not recorded user decisions.

## Goal and scope

Give command-line tools and services access to their execution environment and a way to shut down deliberately.

Recommended first slice: platform identification (requested 2026-11-17), program arguments, environment reads and mutation, working-directory reads, and exit status. Recommended second slice: signal subscriptions for graceful shutdown. Defer changing directory because it races relative-path filesystem jobs. Environment mutation remains a recommendation, not an accepted decision. Child processes belong in a separate design; path manipulation, random generation and terminal controls stay with their respective modules.

## Backend policy (user decision, 2026-11-17)

Prefer Zig std wherever practical. Use libuv for signals, which must integrate with the existing event loop. Environment and cwd do not require libuv.

| API | Backend |
| --- | --- |
| platform | builtin.os.tag mapped to the public enum |
| args | std.process.Init.minimal.args, passed through Dusk into VM |
| env | std.process.Environ or an explicitly supplied environment map; define snapshot/live semantics before implementation |
| cwd | std.process.currentPathAlloc using the host's std.Io |
| set_exit_code | Per-run VM state propagated to the host/CLI |
| set_env / unset_env | Pending backend decision: installed Zig 0.16 has map mutation but no portable host-environment setter found. A map update does not update the host environment. Prefer small platform bindings for actual host mutation if included; do not silently substitute map-only semantics or introduce libuv for these calls. |
| signal subscription/wait/close | libuv watcher lifecycle plus the existing scheduler |

Installed Zig 0.16 was inspected in std/process.zig and std/process/Environ.zig. Init supplies both minimal.environ and environ_map. Environment lookup must use the selected environment source consistently with any future writes; a startup map must not be described as a live host lookup. Pass std.Io explicitly from the embedding host for cwd. Validate returned text under Dusk's UTF-8 rules, including platform encodings that permit more than valid UTF-8.

## Proposed API and behavior

Signatures below are design sketches, not implemented declarations. Error names are provisional.

| Operation | Proposed signature | Proposed behavior |
| --- | --- | --- |
| Platform | `platform() -> Platform` | Operating system targeted by the running Dusk runtime; never fails. |
| Program arguments | `args() -> OsError![]string` | Only arguments after the script path; excludes runtime executable and script path. An owned snapshot on every call. |
| Environment lookup | `env(name: string) -> OsError!?string` | Missing is null; an empty value is an empty string. Reject invalid names and invalid UTF-8. |
| Working directory | `cwd() -> OsError!string` | Current absolute process working directory; not the entry module's directory. |
| Default exit status | `set_exit_code(code: int) -> OsError!void` | Execution continues; status is used on normal completion of all tasks. A runtime failure still exits unsuccessfully. Recommend accepting 0 through 255. |
| Environment update (recommended) | `set_env(name: string, value: string) -> OsError!void` | Changes process environment for all tasks. |
| Environment removal (recommended) | `unset_env(name: string) -> OsError!void` | Missing name is a successful no-op. |
| Change directory (deferred) | `chdir(path: string) -> OsError!void` | Process-wide; affects all future relative filesystem operations. |

Platform is included by user request (2026-11-17). Proposed representation: a `Platform` enum with `Linux`, `MacOS`, `Windows`, and `Other`; names and variant coverage remain proposals. It describes the runtime target OS, including when cross-compiled, rather than the machine that built it. Architecture, OS release, distribution and capability detection are separate concerns. Return a constant enum value without allocation or system calls.

Suggested initial OsError vocabulary: InvalidArgument, InvalidUtf8, NotFound, PermissionDenied, Unsupported, Other. Finalize it against the actual operations before implementing; do not silently replace invalid text. Allocation failure follows existing native conventions.

Arguments need a documented CLI contract: `dusk program.dsk arg1 --flag` exposes `["arg1", "--flag"]`; argument parsing stops at the script path. Embedded runs receive arguments explicitly, defaulting to empty. Keep argument storage alive across execution and allocate returned values using the normal GC rules. Script and executable paths, if later exposed, get separate functions.

Environment names reject empty strings, NUL and `=`; values reject NUL. Lookup uses host case rules. A snapshot cannot change when a caller mutates a returned value. Enumeration of the entire environment is optional later.

Changing directory is particularly consequential: filesystem jobs already execute on pool threads, so a concurrent chdir can race relative path resolution. Prefer omitting chdir initially. If included, decide whether every path is made absolute at submission, and specify how it interacts with SSL_CERT_FILE / SSL_CERT_DIR and other relative configuration paths. Do not promise task-local working directories.

## Exit policy to decide

Recommend `set_exit_code` first: it allows ordinary resource cleanup and avoids adding an expression that never returns when Dusk has no public never-returning type.

An immediate `exit(code)` is a separate decision. If desired, define its static control-flow behavior, how it stops all tasks, flushing of stdout/stderr, native resource teardown, and what an embedded host receives. Avoid terminating the host process from a builtin. Stopping tasks is not equivalent to executing user cleanup; cancellation and defer semantics are separate work.

Normal completion means the runtime finishes according to its existing task-liveness rules. Setting an exit code must not suppress runtime failures or unhandled task failures. Decide whether nonzero codes from several tasks use last-write-wins (recommended for an explicitly process-global setter).

## Signals: recommended design direction

Prefer an explicit subscription over a bare one-shot wait: subscribe before serving, so a signal between registration and waiting can be retained. Proposed shape: `watch_signal(signal) -> OsError!SignalStream`, with `wait()` and idempotent `close()`. A subscription has one waiter; another concurrent waiter fails with Busy. Closing wakes a parked waiter with Closed. Final signatures/error ownership remain open.

Start with Interrupt and Terminate where supported. Do not expose raw signal numbers as a portable API. Unsupported signal/platform combinations fail explicitly. On Windows, libuv can receive console Interrupt, but Terminate watchers never receive notifications; do not present Terminate as portable there.

Specify one pending notification per subscription, coalescing repeated arrivals rather than promising a count. Separate subscriptions receive their own notification. Default signal behavior remains in place when no subscription is active; stopping the last subscription must be tested. Decide what a second Interrupt should do while cleanup is running.

Runtime ownership follows timers and streams: C-side subscription memory, HandleOwner dispatch, loop callbacks only record notifications or wake tasks; no Dusk execution or allocation in callbacks. Close handles asynchronously before freeing memory; parked waiters stay GC roots. Active subscriptions/waits and task liveness must be specified, including teardown when the main task finishes.

## Implementation phases

Each phase ends with its focused validation and a granular commit. Keep this plan and task tracking current as implementation proceeds. Do not implement the deferred APIs as part of these phases.

### P0: lock the public contract

- [ ] Confirm the recommended first-slice API in the table, including environment mutation and set_exit_code instead of immediate exit.
- [ ] Confirm Platform variants and signal scope; first slice can ship independently of signals.
- [ ] Finalize OsError with only variants actually used. Signal-only errors belong to the signal phase.

Exit criterion: record concrete decisions here before implementing the affected API. Platform inclusion is already accepted; its enum representation is the recommendation.

### P1: module, platform and execution context

- [ ] Add src/runtime/builtins/std/os.dsk and os.zig; register them in src/runtime/builtins/std.zig.
- [ ] Implement platform() as a native returning the enum ordinal selected from the runtime target. Keep the mapping and enum order covered by tests; no reflection or compiler dependency.
- [ ] Add explicit argument input to Dusk with an empty default; pass a borrowed immutable slice into VM for the duration of a run. The host owns the backing bytes until execution ends.
- [ ] Add per-run exit status initialized to zero in VM and expose the successful result to the Dusk host. Recommended compatibility approach: keep runFile/compileAndRun/runProgram returning !void and add an exit_code field on Dusk; reset it before each run and copy it out only on success. A failed run reports its existing error and resets the host status to failure.
- [ ] CLI passes args after the script path into Dusk, preserves --version handling, and uses the selected exit status only after the runtime returns and output flush/cleanup has completed. Avoid an early process exit that skips cleanup.

Files: src/main.zig, src/dusk.zig, src/runtime/vm.zig, new std/os pair, registry, src/test.zig.

Exit criterion: existing host calls remain valid; import std/os and platform() work; repeated executions do not leak arguments or exit status from an earlier run. Preserve VM.execute alignment and avoid changing dispatch layout for this feature.

### P2: arguments, environment and cwd

- [ ] Implement args() with full UTF-8 validation before exposing strings and a fresh array per call. Size all strings and the array, collect once, then construct the result without retaining moving heap pointers across allocation.
- [ ] Implement env(name) through std.process.Environ/map lookup and cwd() through std.process.currentPathAlloc; resolve snapshot/live environment semantics and the host-mutation backend before implementing set_env/unset_env. Use growable temporary C/host allocations for variable-length outputs, release on all exits, then create GC values.
- [ ] Use Zig std for environment reads and cwd, passing environment context and std.Io from the host. If a shared adapter is useful, place it in src/runtime/os.zig; no libuv declarations or event-loop initialization for these operations. Add platform bindings only for an operation Zig std cannot supply.
- [ ] Validate names and values before host calls or map access. Preserve empty environment values and reject invalid UTF-8; never expose a borrowed host string as a Dusk heap string.
- [ ] Keep process-global environment operations on the loop thread. Audit pool-thread environment readers, especially trust_store.zig, before enabling mutation. Copy needed environment values on the loop thread before submitting work, or use one shared synchronization policy for all such readers/writers. Include concurrent embedded VMs in the policy; if this cannot be made reliable in scope, defer mutation explicitly.
- [ ] Keep cwd read-only. Do not add script/executable path queries or environment enumeration in this slice.

Exit criterion: missing environment values differ from empty values, UTF-8 and input validation are consistent, and OS resources/temporary buffers have no leaks. Module bindings and error mirrors pass existing consistency tests.

### P3: exit status

- [ ] Implement set_exit_code with 0..255 validation; invalid input leaves the previous code intact.
- [ ] Store the code per VM execution; the last successful setter call wins, including zero. Do not stop tasks or alter scheduler liveness.
- [ ] Runtime errors and unhandled task failures retain their failure path regardless of the selected normal exit code.
- [ ] Test CLI status propagation in subprocesses, flushing of buffered output, host return control and per-run reset.

Exit criterion: a normal program controls its status without aborting other tasks or terminating an embedding host. Immediate exit remains deferred.

### P4: signal subscriptions

Recommended public contract for this phase:

| Declaration | Meaning |
| --- | --- |
| Signal enum: Interrupt, Terminate | Semantic names mapped to supported host signals. |
| watch_signal(signal: Signal) -> OsError!SignalStream | Subscribe immediately; unsupported delivery fails with Unsupported. |
| SignalStream.wait(self: @) -> OsError!void | Consume pending notification or park until notified; Busy for a second waiter. |
| SignalStream.close(self: @) -> void | Idempotent; wake a parked wait with Closed. |

- [ ] Add Busy and Closed to OsError in this phase if adopting the signatures above; mirror the exact Dusk order in Zig.
- [ ] Add tasks/signal.zig, an EventLoop subscription table, HandleOwner.signal, and the libuv signal declarations/size lookup. Use an opaque file-only handle in the public Dusk struct.
- [ ] Subscription handles must never resolve to a different subscription after close. Use append-only slots initially, as with current stream tables, or generation-checked reuse; do not introduce unchecked slot reuse.
- [ ] Register the watcher before returning from watch_signal. Retain at most one pending notification when no task is waiting; receiving a notification with a waiter wakes once without also leaving a duplicate pending event.
- [ ] Keep idle watchers unreferenced in libuv; count a parked wait as a pending operation and reference its watcher until wake/close. A subscription alone does not keep execution alive; a waiting task does. Balance counts/references on every success and failure path.
- [ ] While subscribed, repeated Interrupt notifications use the same coalescing rule; do not add an implicit forced-exit-on-second-interrupt policy. A subscriber can close explicitly to end interception. Verify host default behavior after the last subscription closes rather than assuming libuv restores it as desired.
- [ ] Event-loop teardown stops watchers, closes handles, drains close callbacks, then frees subscription memory. Failed registration follows the same asynchronous ownership rules for initialized handles.
- [ ] Cover Unix Interrupt/Terminate; on Windows reject Terminate subscriptions because libuv does not deliver them. State actual tested platforms in the completion record.

Exit criterion: an HTTP server can register before starting work, receive a shutdown notification and call its existing close API. No task cancellation or automatic user cleanup is implied. Signals unused by a program preserve current behavior.

## Validation plan

- Register every Dusk test in src/test.zig; use the existing extern/binding and mirrored-error tests.
- Platform: verify the enum value against the runtime target; cover each supported target mapping and the fallback.
- Arguments: empty list, order, spaces, flags after the script, Unicode, invalid host bytes and fresh returned arrays. Use a subprocess harness to exercise actual CLI forwarding.
- Environment: missing versus empty, Unicode, invalid names/values, invalid host bytes and any agreed mutations. Isolate process-global tests in child processes.
- Cwd: absolute result and host errors; if chdir is accepted, isolate tests and cover concurrent fs job semantics.
- Exit: child-process checks for default zero, configured status, invalid status, buffered output and runtime-failure precedence. Embedded execution must return control to its host.
- Signals: registration before waiting, coalescing, multiple subscribers, Busy, close while waiting, repeated close, teardown and platform support. Use a child readiness handshake, not timing sleeps; an external timeout catches hangs.
- Run Debug and ReleaseFast suites after implementation. No benchmarks are needed for planning.

## Deferred work and remaining decisions

Recommended defaults are environment mutation included after the concurrency audit, read-only cwd, set_exit_code only, and explicit signal subscriptions in a second slice. Confirm these before their implementation; only std/os planning and platform inclusion have been explicitly requested so far.

Deferred: chdir, immediate exit, child processes, environment enumeration, executable/script path queries, architecture and OS version queries, arbitrary raw signals, signal timeouts, task cancellation and terminal controls. No language/compiler changes are prerequisites for the proposed API.
