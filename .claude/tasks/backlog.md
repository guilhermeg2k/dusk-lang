# Backlog

- **SQLite std support (future, user 2026-11-18)**: embed the pinned SQLite C library using the existing dependency-fork approach. First implement the generic native worker infrastructure proposed in `.claude/generic-worker-plan.md`; SQLite uses a dedicated instance. Plan its public API, per-connection ordering/transaction ownership, native result limits, interruption/lock waits and connection shutdown separately. No SQLite implementation requested yet.

- **Reuse closed signal subscription slots** (std/os, 2026-11-17): subscription slots are append-only for stale-handle safety, matching existing stream tables. Consider generation-checked reuse for programs that repeatedly subscribe and close; each closed subscription currently retains one null pointer slot until VM teardown.

- **Host environment mutation (deferred beyond v0.17, user 2026-11-17)**: set_env/unset_env are excluded from this version. Revisit host versus map semantics, Zig std/platform bindings and synchronization with native environment readers if scheduled later. Plan: `.claude/v0.17-os-plan.md`.

Prioritized, top first. Language features planned per version live in `doc/roadmap.md`. This list is for concrete work items and known bugs.

## High
- **Codec field metadata (design talk, user 2026-11-16: "we gonna come back on that later")**: goal is users writing TOML/JSON/XML/YAML codecs for structs. Gaps: (1) per-field metadata: rename (dashes in TOML/YAML keys can't be Dusk identifiers, `@type`, camelCase), skip, omit-null, XML attribute vs element, union representation; (2) per-type custom representation (Timestamp, private-field types): traits are compile-time only, reflection can't call a type's method; (3) ceremony (sessions, try everywhere); (4) speed 5-20x native. Options discussed: global naming/omit_null as codec options (no language change, could go into std/json options now); Go-style string tags (`reflect::tag(field, "toml")`); typed annotations as a general language feature like Java (worth it only if also used for validation, ORM, tests...); self-description (descriptor records methods with a known signature, like field-default callbacks); std/codec data-model layer (format implements ~15 events, std drives reflection), prototyped as a Dusk module first. Lean: naming options -> self-description -> tags; decide tags vs annotations.
- **Struct interpolation prints raw field bits** (bug, 2026-11-16): `format.printValue` prints every struct field as `int64`, so `"${p}"` for a struct with a string field prints its heap address (`{ 140034028916992 }`), and reflection `Value` handles print their cell addresses. Needs a real struct format (field names and values?) or an opaque `<struct Name>`; addresses shouldn't leak.
- **Zero values (TOP PRIORITY, user 2026-11-15: "we need to think about zero-ed values")**: design talk needed before any code. Starting points: whether every type gets a zero value (`0`, `0.0`, `false`, `""`, `[]`, `{}`, `null` for nullables, structs with every field zeroed, the first enum variant?) and where it would apply: `let x: int` without a value, struct fields without defaults (today a field without a default must be passed), `buffer::new(n)` (already zero-filled), growing arrays, map reads of a missing key (today `?V`). Related findings from the anonymous struct fix (39d1a42): `@(a = null)` / `@(items = [])` have no real type (internal `unknown`), `let x = null` and `let xs = [null]` compile without a type. Questions: types with no sensible zero (unions, functions, tasks, file handles later), whether zero values replace or complement nullables, and what happens to struct construction (`Point()` with all fields zeroed?).
- **Hint interpolation on a non-string print** (idea, 2026-11-15): `io::println(5)` gives `Invalid type: expected 'string' found 'int'`; it could add `use interpolation: io::println("${value}")`.
- **v0.16 IO** (design talk 2026-11-14/15). Stay on libuv. Order: `std/io` (stdout/stderr, replaces `echo`, needs `import std/io`) → fs → tcp (+DNS in `connect`, public `std/net`) → stdin (libuv stream) → http server → http client. Groundwork before fs/tcp: handle GC objects pointing to non-moving C state (closed explicitly, GC closes leaked ones like `freeUnreachableTasks`), `WakeResult` payload (bytes in C memory, copied at `finishParkedCall`), common header for libuv requests/handles (`onClose`/`closeLeftoverHandle` assume timers today), one-wake-per-wait record (`Scheduler.wake` doesn't check status; needed for timeouts), parked natives' `error_base`. Fast paths: `uv_try_write` before parking, per-stream C read buffer + `uv_read_stop` backpressure, one allocation per handle. `pending_operations` keeps counting parked tasks only, not open handles. Open: processes, Collections in v0.16, TLS for the client, libuv thread pool size.
  - **Order update (2026-11-15):** stdin moved before TCP as the first user of the stream layer, on libuv streams (`uv_tty_t` for terminals, `uv_pipe_t` for pipes, fs reads when stdin is a file; `uv_guess_handle(0)` picks). Chosen over a thread-pool `uv_fs_read` (holds a pool thread while waiting, can't be cancelled) and a sync read (freezes every task). Terminal features later on the same `uv_tty_t`: raw mode (`uv_tty_set_mode`), size (`uv_tty_get_winsize`), resize (`uv_signal_t` SIGWINCH).
  - **fs slice B: `File` handles (v0.16, user 2026-11-15: after slice A, still in this version)**: `open`/`create` returning a `File`, `read`, `write`, `seek`, `close`, for big files, piece-by-piece reads/writes (logs, line by line) and sending a file to a socket (HTTP server). Designed with the stream layer (handle GC objects, shared read/write shapes with sockets and stdin, the byte builder), before or together with TCP. Built on the same Zig fs core as slice A (pool jobs running sync `uv_fs_*`, payload wakes, errno -> `FsError`); A and B are siblings over that core, A isn't written in Dusk on top of B (each Dusk-level step would cost an interpreter pass, a park/wake and a pool round trip; one native job does open+fstat+read+close in one round trip).
  - **`fs::dir_size(path)`** (idea, 2026-11-15): total size of a folder's contents, walked inside one native job (symlinks: decide). `fs::stat` gives `size = 0` for folders.
  - **`io::write(buffer)` + byte builder** (user, 2026-11-15: later, with streams): `io::write` goes through the same Zig core as `print` (`writeBytes`, strings and buffers are both `Bytes`). Needed with it: writing a string into a buffer at a position (`buffer::put(buf, at, text) -> int`), partial writes (`io::write(buf, n)` or buffer slicing), numbers without allocating (`put_int`), and the real question: fixed `buffer` + offset vs a growable byte builder (`w.put(...)`, `w.clear()`, memory reused) shared by io, fs, net, http (responses, JSON, logs). Large writes can skip the stdout buffer and go straight from the GC buffer (safe: the write is sync). Use case: TUI rendering (back/front grids, diff, one output buffer reused per frame, one write). Also `io::flush()` for exact frame boundaries.
  - **Async stdout (later, only if it matters):** stdout/stderr are sync. A full pipe (`dusk server.dsk | slow-reader`) stalls the whole VM. Once the stream layer exists, stdout could use its write path (`uv_try_write` fast path, park the printing task only when the pipe is full, drain at exit). Careful: `O_NONBLOCK` is shared with the parent shell for pipes (libuv reopens `/dev/tty` for terminals only).
- **Modules design** (v0.15, designed with the user 2026-11-10/11). Plan with phases: `.claude/v0.15-modules-plan.md` (A modules, B std infrastructure, C std moves, D native maps, E generics). Decided:
  - **One file is one module** (not folder = module): `physics.dsk` is module `physics`, `ui/button.dsk` is imported as `@/ui/button`. Folder modules could come later (not the other way around).
  - **Names: qualified by default + selective imports, no glob** (Gleam model): `button.draw(ok)`; selective pulls named things in as plain names; importing a name that already exists (local, prelude, another import) is a compile error. Reasons: traceable names, no clashes between 3rd-party libs, fast/simple language server (completion after `button.`, one lookup per plain name, auto-import). Syntax decided 2026-11-10:
    ```
    import @/physics
    import @/ui/button as btn
    import @/ui/theme: dark, light
    import std/math: sqrt, PI
    import std/fs: read as read_file
    ```
    `import` keyword (familiar); `: names` for selective imports (reuses Dusk's "bind names" meaning of `:` from `for items: item` / `if x: n`, no new punctuation); `as` aliases modules and names. **Module access is `::`, for every module** (changed 2026-11-11, replacing `.`): `physics::step(world)`, `jsonc::read(text)`, `map::len(m)`. Types and values keep `.` (`Color.Red`, `Stack.MAX`, `player.move()`). Modules live in their own namespace, so a module never clashes with a variable or type (`let buf = buf::new(64)` would be fine), and the planned import-vs-local clash error is gone. Precedent: C3 (`io::printn`), Hare (`fmt::println`). Long selective lists continue after a trailing comma.
  - **Paths are bare with slashes**: `ui/button`, no quotes, no extension. A declaration, resolved at compile time (not a call-like `import("...")`: Dusk needs the module's types to check code, so it can't be a runtime load anyway).
  - **Std modules for built-in types are named after the type** (2026-11-11): `std/string`, `std/buffer`, `std/map`, used as `string::split(s, ",")`, `buffer::len(b)`, `map::remove(m, k)`. Type names are lexer keywords (`int`, `string`, `buffer`; `map` becomes one), so `map[` is the type and `map::` the module, and neither can be a variable. They need an import like every module (`import std/map`), no magic. **Dead simple prelude** (2026-11-11): it keeps only `echo`, `assert`, `copy`, `to_int`, `to_float`, `to_byte`, `spawn`, `await` and `ConversionError`. Everything else moves to `std/<type>`:
    - `std/array`: `len`, `append`, `pop`, `pop_or_null`, `insert`, `remove`, `clear`, `index_of`, `contains`, `reverse`, `slice`, `ArrayError` (`len`, `append`, `pop` stay intrinsics through `std/array.zig` bindings).
    - `std/string`: every `str_*` without the prefix (`string::split`), `string_from`, `StringError`.
    - `std/buffer`: `buffer_len` -> `buffer::len`, `new_buffer` -> `buffer::new`, `buffer_from` -> `buffer::from_string`, `BufferError` (and `string_from` -> `string::from_bytes` in `std/string`).
    - `std/map`: `map::len`, `remove`, `has`, `keys`, `values`, `clear`.
    - `std/task`: `task::sleep(ms)` (user's choice 2026-11-11 over `std/time`: pausing is about tasks; the parking native moves as is). Later home for channels, cancellation, timeouts. Clock functions would go to a separate `std/time` when the program environment is designed.
    Array types, literals, indexing and `for` stay syntax (no import). Selective imports give plain names back (`import std/array: len, append`). **No shadowing**: a declaration with a prelude name stays an `AlreadyDefined` error; the prelude is small and stable enough that it rarely matters. Compared with Kotlin/Rust (big automatic sets, possible through methods on types + shadowing, which Dusk doesn't have), Go (magic built-ins `len`/`append` + packages), Gleam/OCaml (modules, closest), Zig (only `@` built-ins), C (nothing). Big breaking change: migrate tests, examples and docs in one go.
    Module details (confirmed 2026-11-11): an imported module may have `main` (ignored when imported); generic copies checked in their defining module's context (generalize `enterPreludeContext`); traits work across modules unchanged; error set ids assigned as modules compile in dependency order; messages/`echo`/LSP show other modules' types qualified (`physics::World`). Opaque native types (`File`, sockets): design with IO (v0.16). This replaces the `map_*` prefix decision: map functions are `map::len`, `map::remove`, `map::has`, `map::keys`, `map::values`, `map::clear`, and `str_*` become `string::*` without the prefix.
  - **Std layout approved** (2026-11-11): `src/runtime/builtins/` holds `prelude.dsk` + `prelude.zig` (today's `natives.zig`), `std.zig` (registry, one line per module: path, `@embedFile` of the `.dsk`, `@import` of the `.zig`), and `std/<name>.dsk` (declarations: `extern func` + Dusk functions, `~` for private helpers) + `std/<name>.zig` (natives + that module's `bindings`). Bindings are per module; the extern/binding test loops over every module. `extern` allowed in the prelude and std modules only; std sources embedded in the binary, compiled only when imported. `~` replaces the prelude's `__` rule.
  - **Error ids for natives** (2026-11-11): natives fail with the variant's position in its set, typed through a Zig enum mirroring the `.dsk` declaration (`const StringError = enum { OutOfRange, NegativeCount, InvalidUtf8 }; return fail(StringError.OutOfRange);`). Ids stay consecutive per set, each extern fails with exactly one declared set (its `E!T` return type), the compiler stores that set's first id with the extern, and the VM adds it on failure (failure path only). A test checks each Zig enum against its `.dsk` set (names and order). The prelude switches too: the hardcoded `natives.*_id` constants and their test go away. Keeps "std modules compile only when imported" true. `StringError` moves to `std/string`, `BufferError` to `std/buffer`; `ConversionError` and `ArrayError` stay in the prelude. Rejected: all std error sets always registered first (fixed ids), lookup by name.
  - **Visibility** (2026-11-10/11): **public by default**; a marker on the declaration (never at use sites: calls and field reads use the plain name) makes something file-only. One rule for top-level functions, types, constants, fields and methods. **Marker: `~` before the name** (chosen "for now", 2026-11-11): `func ~integrate(...)`, `struct ~Body`, `let ~SCRATCH = 256`, field `~history: []int = []`, method `func ~trim(mut self: @)`. Precedent: Nim's `*` export marker (opposite default). `~` is unused in the lexer today. Considered: `-` (UML, reads as minus), `&`, `^`, `local` (clashes with "local variable" wording), `private`, `priv`, `hidden`, `internal` (library-level elsewhere). Outside the file, struct construction can only set public fields: a private field with a default doesn't block `Counter(count = 0)`, one without a default means only the file can build the struct (opaque for free, no `opaque` keyword). Static fields, enum and union variants follow their type. **Private types in public signatures are an error** (like Kotlin/Rust; agreed 2026-11-11). Later: a library-level visibility (Kotlin `internal`) later, when libraries exist. Rejected: `pub` / private by default, Go capitalization, `__` / Dart-style `_name` (visibility in every use).
  - **Import cycles are a compile error** (like Go/Gleam; agreed 2026-11-11): modules are checked in dependency order, error reads like `import cycle: @/a -> @/b -> @/a`. Allowing cycles later wouldn't break anything.
  - **Three kinds of imports, visibly different** (decided 2026-11-10):
    ```
    import std/fs                 # standard library: "std" is reserved
    import json/decode            # library: first part is its name (declared in a manifest later)
    import @/physics              # this project: "@/" is the project root
    import @/ui/button as btn
    ```
    Local paths are relative to the project root (the folder of the file you run), never to the importing file. `@/` marks local, so libraries never clash with local folders (no clash rule) and the project can have folders named `std`/`lib`. `@` keeps its "own type" meaning elsewhere: `@/` only appears right after `import`. The name you use is the last path part (`button`), `as` renames. Selective imports keep the module name too (`import @/ui/theme: dark` also gives `theme.x`). Rejected: `std/` + `lib/` prefixes, `std:` schemes, `@std/` sigils, `./` for local, local marked by `.dsk`.
- **Std prerequisites** (reviewing with the user since 2026-11-10; roadmap now: v0.15 adds Modules, v0.16 is libuv IO + Collections). Decided so far:
  - **HashMap is native (Zig)**, a built-in `Map[K, V]` heap type like `Task[T, E]`: hashing and key comparison live in the native, so primitives don't need `Hash`/`Eq` traits and string keys compare by content.
  - **No bitwise operators or wrapping arithmetic** for now.
  - **Insertion order**: dense entry array + small index table (like `std.ArrayHashMap`), removal marks a tombstone and compacts when gaps pile up (Zig's swapRemove loses order, orderedRemove is O(n), so likely our own table).
  - **Looping is built into `for`**: `for scores: score, name do` (value then key, like arrays' item then index; `_` skips either), plus `keys(m)` / `values(m)` returning arrays. Changing the map during a loop is allowed: a removed entry the loop hasn't reached is skipped, an added one is seen at the end. No iterator protocol for user types now (Kotlin-style iterator()/next() rejected as too much); if ever needed, Go-style range-over-function (loop body becomes a callback) fits since closures exist.
  - **Get/set are index syntax, the rest are plain functions** (no methods on built-in types: keep primitive types simple). `m[k]` reads a `?V` (missing key = `null`, use `orelse` / `if m[k]: v`), `m[k] = v` sets, `m?[k]` reads from a `?Map` (new, needed for chains like `players[10]?.pets?["gerolenda"]` and `grid[x]?[y]`). Others are prelude functions like today's builtins: `map_remove(m, k)`, `map_has(m, k)` (needed when `V` is nullable), `len(m)`, `keys(m)`, `values(m)`, `map_clear(m)` (exact names still to confirm). Writing through `?.` stays unsupported, like for fields: use `if m[k]: mut v`.
  - **Type and literals**: the type is written `map[string, int]` (lowercase, slots in brackets). Literal `{"ana": 10, "bob": 7}`, nested `{1: {1: "x"}}`; empty is `{}` and needs an expected type, like `[]` (`let scores: map[string, int] = {}`). Braces are new in Dusk (unused so far), so the parser sees a map at `{`. Rejected: `map()` / `map({...})` / `map("ana": 10)` constructors, `[k: v]` brackets.
  - **Key types**: `int`, `string` (by content), `bool`, enums, and structs **by identity** (pointer, not content: two `Point(x = 1, y = 2)` are different keys; the docs must say this clearly). No floats for now (adding later isn't breaking; if added: NaN key = runtime error, `-0.0` stored as `0.0`). `byte` not mentioned by the user, confirm. Sema allows these directly for `map` keys (no need to fix enums in type lists first). Implementation catch: the copying GC moves structs, so an identity hash can't be the address; decided 2026-11-10: a **lazy identity number** in the struct header (`identity: u32` fits the 5 padding bytes after `field_count`, so structs don't grow; `Struct.clone` memcpys the header so GC moves keep it). `0` = not assigned; the map native assigns it from a VM counter the first time a struct is hashed (struct allocation stays untouched). `copy(x)` gives the copy `0` again. Equality stays pointer comparison; the number only picks the bucket, so counter wrap-around is harmless.
  - Agreed 2026-11-10: `byte` keys too; `m[k]` is always `?V` (missing key and stored `null` look the same, `has` tells them apart); `echo(m)` prints `<map>`; deep `copy(m)` (struct keys keep identity); `m[k] = v` / remove need `let mut`, like arrays; literal types from entries with int->float promotion, duplicate constant key = compile error; generic `map[K, V]` params check `K` when the slot is filled (no `Key` constraint). **Function names: now `map::len`, `map::remove`, `map::has`, `map::keys`, `map::values`, `map::clear` in `std/map`** (see Modules design; first decided as `map_*` prelude functions). Rejected: plain names (clash with the array `len`/`clear`/`remove`/`contains`, Dusk has no overloading), prelude-only overloading and Go-style magic builtins (user doesn't want overloading or special cases in the compiler), a `maps` std module.
  - **Equality rule**: immutable values compare by content (numbers, bool, enums, **strings**), mutable objects by identity (arrays, structs, maps, buffers, unions). So `==` on strings becomes content comparison and **`str_equal` is removed**; maps compare by identity. Also drops the "type list without `string`" exception for `==` on `T`.
  - Generic limits A and D: own backlog items below. B, C and E stay as they are (no `f[int]()`, no static methods in traits, no lambda params from a result-only slot).
  - Dropped for now (user, 2026-11-10): Sets and Tuples.
  - Std modules declaring natives: designed in the Modules design item (layout, registry, error ids); only opaque native types are open. Program environment (args, stdin, exit code, env, clock, random): not now (user, 2026-11-10).
- **Methods with their own type slots** (generic limit A, decided 2026-11-10): `func map[U](self: @, f: func(T) -> U) -> Box[U]` on `struct Box[T]`, also on non-generic structs, enums and unions. Rust and Kotlin allow it; Go doesn't. Work: methods are parsed with `parseFuncSignature(false)` (no slots) and `createMethodSignatures` stores name -> one function type, so a generic method needs its own entry kind; copies keyed by the struct copy + the method's slot types (`instantiateGenericFunction` machinery), the struct's slot scope around the method's; slot inference (and lambda param typing) on the `x.m(...)` call path; the "checked where written" pass for a generic method on a generic struct. Traits requiring generic methods can wait. The hardest of the std prerequisites.
- **Type lists take any type** (generic limit D, decided 2026-11-10): `[T: int | Color]`, `[T: Circle | Square]`, arrays, unions... today `isTypeListMember` (`sema.zig`) only accepts `int | float | byte | string | bool`. Check each per-member rule with heap members (operators, conversions like `let x: T = 0`), decide nullable members (likely still rejected), and make `index_of` / `contains` compare heap members by identity (strings by content once `==` on strings compares content). Also closes the "Array search on enums" limitation in language-ref §16.

  - Done 2026-11-16: `value` is a view (no copy), `set_field`/`check_input` natives, public `null_of`/`enum_value` (~20% on decode, bulk and encode; now 7.8x / 13x / 20x / 5.3x native).

## Medium
- **Process and pipe slot reuse** (std/process, 2026-11-18): closed process records and stream objects are freed, but append-only table slots remain for stale-handle safety. Consider generation-checked reuse for long-lived programs repeatedly launching children.
- **Windows process runtime conformance** (2026-11-18): x86_64-gnu cross-build passes; run the portable fixture and CLI lifecycle harness on Windows, including Unicode argv/quoting, PATH entries, required environment supplementation, pipe EOF and forced termination. Fixture narrow main argv encoding may need a wide-entry adapter for Unicode verification.
- **Nullable when default/null branch roots** (inspect after the if/else root fix, 2026-11-16): genWhen emits the default block before a separate null body without obviously resetting default-local registers. Audit for the analogous stale-root hazard using a focused reproducer before changing it.
- **Investigate native sort_by** (user-requested benchmark, 2026-11-15): existing interpreted heapsort with an ascending integer callback takes about 11–12x the native default sort at 1k/10k/100k items (raw results in `benchmarks/history/array-sort-compare-0ec8b8b.json`). Native iteration would still pay Dusk callback costs; measure that separately before promising a speedup. Needs a safe native-to-Dusk callback path (GC, errors, tasks).
- **More unboxed map reads** (found 2026-11-14, maps CR): sema lowers `m[k]` to `MAP_FIND` (no box) only for `if m[k]: v` and `m[k] orelse d` (`lowerUnboxedMapRead`). Other reads go through `MAP_GET`, which allocates a box for a primitive, non-nullable `V` (`int`, `float`, `bool`, `byte`, enum) on a non-nullable map; heap-type `V` never boxes. Same conditions as `lowerUnboxedMapRead`. In order of value: (1) `m[k] == null` / `!= null` (the null branch of `.eq`/`.not_eq` in sema, `left_is_nullable and right_is_null` and the mirror case) boxes only to test for null: use the `found` flag (`not found` for `==`). Smallest and most common, since it's the natural "is the key there?" check (`map::has` doesn't box). (2) `m[k] == 5` (`lowerNullableEquality`): `found and value == 5`, branch work like `lowerOrelseBranch`. (3) `when m[k]` with a `null` prong (`resolveWhenSubject` never calls `lowerUnboxedMapRead`): flag for the null prong, raw value for the rest. Tests in `test/success/` check results only; the missing box shows up only in a benchmark or an allocation count.
- **`slice` builds its result one item at a time** (CR release..main, 2026-11-08): the prelude `slice` does `append(out, copy(array[i]))`, so a 100,000-item slice regrows `out` ~20 times. A native `__array_slice` that sizes the result once (like the other allocating natives) fixes it; keep the prelude wrapper for the bounds checks.
- **Runtime errors find the top-level frame by its `$` name** (CR release..main, 2026-11-08): `reportErrorLocation` (`vm.zig`) skips frames whose name starts with `$`, and reports prelude functions (`reverse`, `pop`) as if they were user code. Mark top-level/prelude functions when codegen builds them. Decide first: should an error inside `reverse` name `reverse` or its user caller?
- **v0.13 is 21–82% slower than v0.11 on the VM benchmarks** (full report 2026-11-05, commit 49f2bd0; ratios vs native Zig got worse too, so not noise): fib +21% (413 → 499 ms), particles +82% (459 → 835 ms), primes +36%, quicksort +30%, mandelbrot +40% (7.7 → 10.8 s). Mandelbrot/primes/quicksort match the known builtins-refactor and `CALL` effects the user accepted; particles was never measured in isolation and is the biggest jump. Bisect with `python3 bench.py --json particles --compare <ref>` across the 0.13 commits (struct/array paths, immutability, tail calls, `CALL` bounds check) when the user asks. Update 2026-11-13 (3a83e52, after maps): fib 403 ms, particles 507 ms (noisy), mandelbrot 7.5 s, back near v0.11; only primes/quicksort not rechecked against v0.11.
- **Builtins return errors instead of runtime errors** (user, 2026-11-03; breaking is fine): decide per function. Natives can already fail with an error id (`fail(id)` in `natives.zig`), so each change is a prelude signature (`-> E!T`) plus the native. Indexing (`xs[i]`, `BYTES_SET`) and buffer creation are opcodes, not natives: deciding those is a language question (checked `get(xs, i) -> ?T` natives are one option).
- **`copy(x)` makes system calls on every call** (found 2026-11-05, not measured): `deepCopy` (`vm.zig`) builds its `copies` map and `pending` list with `self.allocator`, which is `std.heap.page_allocator` (`VM.init`). Every first allocation, growth and `deinit` is an `mmap`/`munmap`, so even `copy` of a small struct pays at least 4 syscalls, likely more than the cloning itself. Matters for the `append(self.items, copy(item))` pattern the sharing rules encourage. Fix options: keep `copies` and `pending` on the VM and `clearRetainingCapacity` after each copy (no allocation after warm-up), or give the VM a general-purpose allocator (`smp_allocator`) for its bookkeeping and keep `page_allocator` only for the big `allocUntouched` stack/frames. `heap.gc_queue` also uses `page_allocator` (`clearAndFree` + `ensureTotalCapacity` on arena reset), less often. Add a `copy`-heavy benchmark first to measure before/after.
- **`assert` panics the whole process** (`@panic("ASSERTION_FAILED")` in `natives.zig`): make it a runtime error (`RunTimeError.AssertionFailed`) with a message.
- **`echo` and the `dynamic` type are stand-ins for traits**: `append`, `copy` and `len` are generic since v0.14; `echo` still takes `dynamic` with a hidden kind argument. Replace it once there's a `Printable` trait.
- **Reuse task stacks** (2026-11-09): each `spawn` allocates a 1024-slot stack + 32 frames with the C allocator and `finish` frees them. A free list of default-size stacks in `Scheduler` would make spawning thousands of short tasks cheaper (measure with a spawn-heavy benchmark first).
- **Benchmark the builtins refactor**: natives now go through `CALL` (changed the `CALL` handler in `VM.run`). Run `python3 bench.py --json fib strings concat parse --compare d16a822` when asked.
- **VM dispatch refactor**: move `VM.run` to labeled switch dispatch (`continue :dispatch`). Keep cold paths (allocation, GC) out of hot handlers with `@branchHint(.cold)` or `noinline`, and avoid `try` in hot handlers. Goal: faster and less sensitive to code layout (unrelated edits currently move `fib` by up to ±50%).
- **Struct printing**: `echo` on a struct prints every field as an int (e.g. `{ 139863671763328 }`).
- **Union printing and interpolation**: `echo(u)` and `"$u"` print `<union>`. Show the active variant name and formatted payload through the shared formatter. Needs variant names in the union descriptor; cover nullable unions and unions nested in arrays too.

## Low
- **Random library follow-ups** (deferred after initial v0.17 scope, 2026-11-17): shuffle/choice/sample, weighted choices, in-place buffer fill and a question-named boolean/probability helper. Revisit generic-method limitations before adding Generator collection methods. See `.claude/v0.17-random-plan.md`; no global reseed API is planned.
- **Runtime `unreachable`s are unchecked in ReleaseFast** (2026-11-14): the compiler ones became `@panic` (538618d), the runtime ones stayed for speed: `vm.zig` `CALL` on an intrinsic and the `else` of the `VM.run` opcode switch, `value.zig` map key types (`hashKey`, one more), `format.zig` (2), `bytecode.zig:122`. Safer: make the opcode switch exhaustive (no `else`), so a forgotten opcode is a compile error; touches `VM.run` layout, so benchmark it.
- **Compile caching (idea, 2026-11-14)**: research and options in `.claude/module-caching-notes.md`. Cheap first step: cache the whole program's bytecode keyed by hash(dusk version + every loaded file); later, per-module caching (per-module numbering + import tables linked at load, module interfaces, generic copies merged by name), which also enables analyzing modules in parallel along the dependency graph. Measure compile vs run time first. Not planned yet.
- **Parked natives with a declared error set** (2026-11-11, B2): errors delivered through `Scheduler.wake` are absolute ids, while immediate native failures are relative to `error_base`. When v0.16 IO natives park and fail (`FileError`), `finishParkedCall` should add the parked native's `error_base`, or wakers must pass absolute ids.
- **Methods aren't module-qualified at runtime** (2026-11-11, A5): runtime errors name a method `increment`, not `counter::Counter.increment`.
- **Source lines for runtime errors** (2026-11-07): runtime errors now name the function (`VM.reportErrorLocation`), but bytecode keeps no instruction-to-line map, so there's no line number. Adding one would improve every runtime error.
- **Missing conversions** (2026-11-07, after `to_byte`/`to_int`/`to_float`):
  - Enum ↔ `int`: no way to get an enum's number or build an enum from one (saving data, file formats, protocols). Naming is per type, user to decide; suggestion: `Color.Red.value()` and `Color.from(n) -> ConversionError!Color` (fails for an unknown number).
  - Enum → variant name as a `string`: `"$c"` prints the number (overlaps the "Enum printing and interpolation" item).
  - `byte` → one-character `string`: `"$b"` gives `"97"`, not `"a"`; e.g. `str_from_byte(b)`.
  - `string` → `bool`: e.g. `str_to_bool("true") -> ConversionError!bool`.
  - `bool` → `int`: covered today by `if flag then 1 else 0 end`; maybe `to_int(flag)` if `to_int` ever accepts more than `float`.
- **`index_of` / `contains` on enums** (2026-11-06): they're constrained to `int | float | byte | bool | string` because type lists hold primitives only. Enums are int values at runtime, so the native already compares them; allowing enums in type lists (or a separate equality rule) would open them up. Also undecided: struct/union equality.
- **`min` / `max` / `sum` builtins** (idea, 2026-11-06): natural `[T: int | float]` prelude functions in Dusk; not added yet (would clash with user functions of the same name, see the next item).
- **User declarations can't reuse prelude names** (found 2026-11-06; mostly solved by the v0.15 std move: only `echo`, `assert`, `copy`, `to_*`, `spawn`, `await` remain): prelude functions live in the user's root scope, so a top-level `func insert` / `func pop` (or later `reverse`, `sum`, ...) is an `AlreadyDefined` error. Every new prelude function can break existing programs. Options: let user top-level declarations shadow prelude ones (prelude code keeps its own; needs the prelude in a parent scope of the user root, and the many "walk to root" lookups in `sema.zig` to stop at the user root), or wait for modules (0.18).
- **Auto-dispatch unions (idea, not decided)**: `union Entity: Actor` where every variant fits the trait `Actor`; the union then fits it too, and `e.update(dt)` lowers to the `when` the user would write by hand (tag check + direct call per variant). Removes per-method `when` boilerplate for closed sets (game entities, shapes, AST nodes). No vtable, no VM/GC change. Still a closed set: open sets across modules would need real trait values, to be decided when modules (0.18) land. Depends on generics/traits (0.14).
- **Zero / default values (design idea)**: today every value must be given explicitly. `let x: int` and a static `let mut count: int` with no value are syntax errors, and `P()` that skips a field without a default (even a `?int` field) is an "Invalid number of arguments" error. Decide whether to allow leaving values out:
  - **Nullables only**: a missing `?T` value defaults to `null` (`let x: ?int`, an omitted `?T` field). Small and unambiguous.
  - **Zero values for everything**: `0`, `0.0`, `false`, `""`, `[]` and `null`; structs fill each field with its zero value. Open questions: enums (first variant?), unions and error sets have no obvious zero, and struct fields that are other structs would allocate recursively.
  - **Keep requiring values**: improve the messages instead (e.g. name the missing field rather than counting arguments).
  - Related: the High item "Struct field with neither a type nor a default" is fixed by requiring `: Type` or `= value`. That fix stays the same either way, since a field with a type but no default would just get a zero value.
- **Member order isn't enforced**: the language reference says members must come in order (static fields, then fields or variants, then methods) for structs, enums and unions, but the parsers (`parseStructDef`, `parseEnumDef`, `parseUnionDef` in `parser.zig`) accept any order. Fields after a method, a static after a field, an enum variant after a method and a union static after a variant all compile and run correctly. Decide: enforce the order with a parser error, or drop the rule from the docs.
- **Errors: `if`/`when` directly on failing calls**: today a failing call must go through `try`/`catch` first.
- **Enum printing and interpolation**: `echo(Color.Red)` and `"${Color.Red}"` print the numeric value. Preserve enum type/variant metadata at runtime and print a readable name through the shared formatter. Decide how to format aliases with the same numeric value; cover nullable enums and enum arrays too.
- **Error printing and interpolation**: `echo(ParseError.Empty)` and `"${ParseError.Empty}"` print the global id. Show the error name through the shared formatter; names already exist in `Program.error_names`. Cover declared and inferred error sets, nullable errors and error arrays too.
- **Errors: payloads**: error sets have no payload, so errors can't carry a message or context.
- **Infinite loops count as returning**: `for true do ... end` with no `break` that targets it never reaches the end, so it should satisfy `areAllPathsReturning` (`sema.zig`). Today a function ending in such a loop still needs a trailing `return`.
- **Dead code after `return`**: statements after a `return` (or after an `if`/`when` where every branch returns) are compiled but can never run. Report them, as an error or a warning once warnings exist.
- **Payload-less union variants** (e.g. `none`), allowing the type annotation to be omitted.
- **Content comparison for heap types (idea)**: since 2026-11-07, `==` compares identity on arrays, structs and buffers and is an error on strings and unions (user decision). Content-comparison functions per kind (`array_equal`, `struct_equal`, like `str_equal`) are still missing.
- **Bench stability**: have `bench.py` pin to one core (`taskset`) and report min-based comparisons when medians are close.
- **String API follow-ups**: `str_find_last`, `str_trim_start`/`str_trim_end`, `str_lines`, padding (`str_pad_start`/`str_pad_end`), `str_reverse`, `str_replace_first`, strip prefix/suffix, splitting into characters, looping over characters (code points), Unicode-wide case mapping and whitespace, slices as views instead of copies, and a string builder for appending in loops.
- **Mixed positional and named arguments**: a call must be all positional or all named, so an optional parameter can't be named after positional ones (`str_equal(a, b, ignore_case = true)` is a syntax error; write `str_equal(a, b, true)`). Consider allowing named arguments after positional ones.
- **Unsigned ints (idea)**: rejected for the string API (2026-11-01), since counts and positions stay `int` and bad values are errors. Could come back as its own topic (bit manipulation, hashing), needing separate numeric opcodes.
- **Strings: raw strings and line continuation**: no raw form (no escapes, no interpolation), and no `\` at the end of a `"""` line to join it with the next one. CRLF line endings are not normalized: a `\r` before a line break stays in the text.
- **Mutability model (2026-11-07)**: `let` / `let mut`, mutability from the root of the access path, `mut` params/captures/`mut self`, temporaries can be changed. The sharing rule is gone; one local check stays (`ReadOnlyIntoMutable`, 1840abb): a value read through a non-`mut` name can't go into a mutable place. Known holes: a function returning its own non-`mut` param launders it (`let mut y = keep(frozen)`), and generic copies don't check bare `T`. For coroutines later: decide what may cross into a coroutine (copy, or only values nothing `mut` can reach).
- **`buffer` follow-ups**: no typed multi-byte reads/writes yet (`DataView`-like `i32`/`f64` access), no copying a range between buffers, no slicing, `==` compares identity, and no `buf?[i]` on a `?buffer`. Strings and buffers share the `Bytes` VM object, so string operations (Phase 3d) should add their helpers there (`bytesEql`, `bytesFind`...) for buffers to reuse.
- **Static-size arrays `[N]T` (deferred)**: little gain while arrays are heap objects. Revisit together with value types.
- **`byte` follow-ups**: no implicit `byte -> float` conversion (`float(b)` works) (`let f: float = 'a'` and `if c then 'a' else 1.5 end` are type errors); compound assignment on a byte variable always fails (`b += 1` is `int`), so a checked `b = byte(b + 1)` is needed.
- **Heap header slimming: move `relocated` into `Array`** (planned 2026-11-14, CR of maps): `HeapValue` is 24 bytes (`kind` + 7 bytes padding, `gc_forward`, `relocated`), but only `Array.resize` (`value.zig`) ever sets `relocated`. Every other object never grows after creation (strings immutable, buffers fixed length, structs/unions/closures/boxes/cells fixed slots, maps grow through their separate `MapStorage`), so they all pay 8 bytes for nothing. Plan (option B): move the field into `Array` (`HeapValue = { kind, gc_forward }`, 16 bytes), keep array items inline so `ARRAY_LOAD`/`ARRAY_STORE` don't change. Call sites: array-only ones (`getArrayFromHeapValuePtr`, `arrayInSlot` in `vm.zig`, `format.zig`, `std/array.zig`, `string::join`'s parts) switch to an `Array` method; the two generic ones (`Collector.copyHeapValue` in `gc.zig`, `VM.deepCopySlot`) only follow the chain when `kind == .array`. Every object's size and `calc_size` users shift by 8 (check the object table in `vm-internals.md` and any hard-coded sizes). Rejected alternatives: (A) split arrays like maps (`Array` header + `ArrayStorage`) also removes chains, but adds a dependent load to every element access, two allocations per array and header/items in different cache lines; (C) reuse `gc_forward` of the dead old array for the relocation, smallest but trickiest with the GC. `VM.run` changes, so benchmark before/after (`bench.py --compare`) when asked.
