# std/path v0.17 implementation plan

Started 2026-11-17 on v017std by user request to plan and implement the module.

## Contract

All operations are lexical text operations using native platform syntax, without filesystem access, current-directory lookup, libuv, symlink resolution, or existence checks. Zig std supplies path algorithms. Explicit base paths keep resolve/relative deterministic; callers can obtain the working directory from std/os when wanted.

| Function | Return | Semantics |
| --- | --- | --- |
| join(parts: []string) | string | Join nonempty parts with native separators; remove duplicate separators only at component boundaries. No dot normalization or resetting on a later absolute part. Empty input produces an empty string. |
| normalize(text: string) | string | Collapse separators, dot and parent components lexically. Empty/cancelled relative paths become a dot; retain leading parent components in relative paths, clamp parent traversal at an absolute root. |
| basename(text: string) | string | Last component, ignoring trailing separators. Root/empty produces an empty string. |
| dirname(text: string) | ?string | Parent component text, ignoring trailing separators. Bare names, empty paths and roots have no parent and return null. |
| extension(text: string) | string | Last component's final extension including its dot; a leading dot alone does not introduce an extension. No extension is an empty string. |
| stem(text: string) | string | Last component with its final extension removed, preserving dotfiles. |
| is_absolute(text: string) | bool | Fully qualified root. On Windows, drive-absolute and UNC/device absolute paths qualify; rooted paths without a drive and drive-relative paths do not. |
| resolve(base: string, text: string) | PathError!string | Normalize text against an absolute base; a later absolute path replaces the base. Reject a nonabsolute base or unresolved drive-relative result with NotAbsolute. |
| relative(from: string, to: string) | PathError!string | Directory-relative path between absolute inputs. Equal normalized paths return a dot. Across Windows volumes, return normalized absolute destination. Relative inputs fail with NotAbsolute. |

PathError initially has only NotAbsolute. Allocation failure follows existing native runtime conventions. These functions accept text without claiming it is a valid or safe OS filename. normalize/resolve do not enforce directory containment; symlinks can make physical traversal differ from lexical results. No expansion of tilde, environment variables, glob patterns or URL escapes.

Windows uses both separators, canonicalizes separators and drive letters during normalization, and handles UNC roots. Other current targets use slash syntax. Keep Windows and POSIX helper algorithms explicitly selectable in Zig tests so both semantics can be exercised on a Linux host. Native Dusk API selects the runtime target.

## Phases

- [ ] P1: add runtime/path.zig lexical helpers, std/path.dsk and std/path.zig, registry and error mirror. Use Zig std algorithms; extension/stem work on the extracted basename so directories never leak into dotfile stems.
- [ ] P2: native result allocation. For slices into GC inputs, snapshot bytes before any GC allocation. For join, read the complete string array into temporary host slices before calling Zig std, then copy the owned result into the GC. Do not retain input pointers across a collection.
- [ ] P3: register Dusk behavior, type-error and GC stress tests; add host-independent Windows/POSIX cases for roots, trailing separators, relative traversal, UNC and differing drives. Include discarded input roots, dotfiles and long results.
- [ ] P4: document semantics, add a v0.17 changelog bullet and roadmap entry. Validate all tests in Debug and ReleaseFast; no benchmarks. Record results, complete tracking and commit implementation.

## Deferred

Implicit-cwd absolute(), physical realpath, filesystem containment, explicit path flavors in the public API, separator/delimiter constants, globbing and filesystem traversal.

## Evidence

Installed Zig 0.16 std/fs/path.zig inspected for join, resolvePosix/Windows, dirname, basename, relativePosix/Windows, extension and stem. resolve is lexical; relative accepts an explicit cwd and can return an absolute path across Windows volumes. The internal helper uses an already-absolute from as that explicit cwd, avoiding host environment dependence.
