# std/random v0.17: design and implementation plan

Started 2026-11-17 on v017std. User requested planning only. All API details below are recommendations for discussion; no implementation is authorized by this planning request.

## Goal

Everyday random numbers and bytes, reproducible generators for tests/simulations, and an explicit source for secret bytes. Use installed Zig 0.16 std APIs; no libuv dependency. Keep random state separate from map hashing and never expose a module-global seed setter.

## Proposed public API

| Function | Returns | Contract |
| --- | --- | --- |
| int(min: int, max: int) | RandomError!int | Uniform integer with both bounds included. Equal bounds return that value; min greater than max fails with InvalidBounds. Supports the complete signed int range without overflow or modulo bias. |
| float() | RandomError!float | Value in [0, 1): zero possible, one excluded. No bounded-float overload initially. |
| bytes(size: int) | RandomError!buffer | Fresh buffer of ordinary random bytes. Negative size fails with NegativeSize; zero produces an empty buffer. |
| secure_bytes(size: int) | RandomError!buffer | Fresh buffer filled by host secure entropy. Same size rules; entropy failure returns EntropyUnavailable, with no weaker fallback. |
| seeded(seed: int) | Generator | Independent deterministic generator. All signed seeds are accepted by reinterpreting their 64 bits. Does not require host entropy or I/O. |

Module int/float/bytes use a lazily initialized VM-local generator, seeded once from std.Io.random. Their possible Unsupported failure covers execution without a host I/O context. Normal Dusk/CLI executions always supply that context. float is fallible for this initialization reason, although it has no argument errors. Whether to keep this fallibility or require initialized context as a VM invariant is an API decision before implementation.

Generator methods:

| Method | Returns | Contract |
| --- | --- | --- |
| int(mut self, min: int, max: int) | RandomError!int | Same inclusive integer bounds. |
| float(mut self) | float | Same [0, 1) interval; no entropy initialization needed. |
| bytes(mut self, size: int) | RandomError!buffer | Deterministic bytes with the same size rules. |

Use `let mut rng = random::seeded(42)` and `try rng.int(1, 6)`. A generator is an ordinary shared struct: aliases advance the same state. `copy(rng)` creates an independent generator at the same point in the sequence. Passing or capturing it for drawing requires mutability, consistently with other mutable structs. No secure method exists on a seeded Generator.

Recommended RandomError variants: InvalidBounds, NegativeSize, EntropyUnavailable, Unsupported. Finalize the exact used set before implementing. Allocation failure remains a runtime allocation error, following existing builtin conventions.

## Semantics to settle

1. Inclusive int bounds: recommended because Dusk range bounds are inclusive. Use explicit min/max with no default upper bound. Examples: int(1, 6) for a die, int(0, count - 1) for an index after checking count is nonzero.
2. Include seeded Generator in the first release: recommended. It makes randomized tests reproducible without globally changing another task's random stream.
3. Keep secure_bytes separate from ordinary bytes: recommended. Ordinary module functions and Generator methods make no security guarantee.
4. Default float return type: proposal is RandomError!float for lazy initialization without mandatory host context. A non-failing float is possible if random-source initialization becomes a VM invariant; avoid silently using a constant seed when context is missing.
5. Same seed plus the same sequence of method calls and arguments reproduces the same outputs within the same Dusk version. Do not promise sequence compatibility across future versions without pinning the engine and sampling rules. Changing how calls are grouped can change results: concatenating bytes(4) twice need not match bytes(8).
6. Invalid bounds, negative sizes and zero-byte requests do not initialize or advance a generator. Equal integer bounds return the value without consuming state. Define these fast paths explicitly rather than depending on Zig helper implementation details. Never assert that two independent random draws must differ.

## Backend and state ownership

- Use std.Random.Xoshiro256 explicitly for the initial deterministic engine, rather than a changing DefaultPrng alias. Seed with the int bit pattern, then use random().intRangeAtMost(i64, min, max), float(f64) and bytes. Validate bounds before Zig's assertion-based helpers.
- For module functions, add optional PRNG state on VM, lazy seeded with 8 bytes from vm.io.random. Construct a temporary std.Random interface at the call site: it contains a pointer to state and must not be cached across moving/copying that state. Each VM has its own state; task scheduling determines which task consumes which draws. A task needing an independent stream uses its own Generator.
- For seeded Generator, prefer four private int fields in an ordinary Dusk struct, storing Xoshiro's four u64 words as int bit patterns. Hidden natives load a local Zig engine and write its state back through a mutable struct argument. A hidden seed-state native can return the initial four words for the Dusk factory to build the struct. This needs no new VM object kind, resource table or finalizer, and ordinary copy duplicates state correctly.
- For secure_bytes use std.Io.randomSecure. Installed Zig documents fresh external entropy with no fallback; it can return EntropyUnavailable or cancellation. Map unavailable entropy to RandomError.EntropyUnavailable; settle cancellation mapping with existing runtime conventions. Missing I/O context is Unsupported.
- Do not use std.Io.random for secure_bytes: it may fall back to a less secure seed source. Do not change the existing Map.randomizeSeeds behavior in this task.
- Calls are synchronous natives and do not park or yield. Secure entropy acquisition can wait in the host OS; do not describe it as asynchronous. There is no worker job or libuv integration in the initial plan.

## GC and allocation

- Validate all inputs and checked buffer-size arithmetic before changing random state or allocating. A rejected request must leave deterministic state unchanged.
- Allocate a fresh Dusk buffer through normal VM/GC conventions. Fill the entire requested buffer, including tails shorter than an engine word. Return no buffer if secure filling fails.
- A generator lives in the moving Dusk heap. Reread the mutable generator argument after any allocation before loading/writing its fields; do not keep a raw struct pointer or std.Random interface into heap memory across collection. A local copied Zig engine is safe across GC, provided its updated words are written back through the reread rooted argument.
- Generic arrays, shuffle and selection are deferred, so the initial API does not need generic methods or new compiler rules.

## Implementation phases (after API discussion and implementation request)

- [ ] P0: agree bounds, API names, default float fallibility, seeded scope and error set. Record accepted decisions here.
- [ ] P1: add runtime/random.zig helpers and std/random.dsk + random.zig, registry and native error mirror. Use the explicit engine and fixed-width sampling. Implement deterministic Generator first, including copy and mutation semantics.
- [ ] P2: add VM-local default state and Zig I/O seeding, then module int/float/bytes and secure_bytes. Keep state per execution and separate from map hashing. Reuse existing host I/O context plumbing from std/os.
- [ ] P3: deterministic, error-path, entropy-injection and GC tests; every Dusk test registered in src/test.zig. Verify hidden state/native visibility and mutability restrictions. No statistical pass/fail tests based on chance.
- [ ] P4: language reference, v0.17 feature bullet and roadmap entry for actual implemented behavior; full Debug and ReleaseFast suites, granular commits and completed task tracking. No benchmarks unless requested.

## Validation

- Seeded replay: two generators with the same seed produce the same mixed method sequence; pin a small set of expected engine/sampling vectors. Include seed zero, negative seeds and int extrema.
- Bounds: equal, reversed, negative/cross-zero, narrow and full signed range. Verify invalid calls and documented zero/equal fast paths do not advance state.
- Floats: deterministic vectors plus 0 <= result < 1; do not require a random endpoint to occur.
- Bytes: sizes 0, 1, 7, 8, 9, long buffers, negative sizes and checked overflow/allocation failure. Verify every byte against deterministic expected output where applicable.
- Sharing/copy: aliases share progress; copy continues independently from the saved point. Non-mut bindings cannot call mutating Generator methods.
- GC: force collection while allocating bytes with a live generator; verify sequence progress, subsequent draws, captured generators and independent copies remain correct.
- Default context: fresh VM state per execution, lazy initialization, independent seeded objects unaffected by unrelated module draws, explicit Unsupported for absent host I/O when a source is needed. Do not test independence by asserting different random values.
- Secure source: inject known bytes/failure through a test std.Io backend, assert the secure hook is used, weaker random hook is never called, failures expose no partial buffer, and zero-size requests do not query entropy. A real-host smoke test can verify successful length without statistical assertions.
- Run on available platforms; record actual target coverage. Cross-version reproducibility is not inferred from tests on one version.

## Deferred

Boolean/probability helper (settle a name consistent with question-prefixed bool APIs), shuffle/choice/sample, weighted choices, random text/tokens, UUIDs, distributions beyond uniform, in-place buffer fill, parallel substreams/jump, async entropy jobs, a public global reseed API and cross-version sequence guarantees.

## Evidence inspected

- Installed Zig 0.16 std/Io.zig: random, randomSecure and RandomSecureError.
- std/Random.zig: IoSource, intRangeAtMost, float and bytes; std/Random/Xoshiro256.zig: explicit engine state, seeding and fill behavior.
